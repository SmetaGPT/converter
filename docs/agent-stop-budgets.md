# Agent Stop Budgets

Дата: 2026-05-22
Статус: active

## 1. Назначение

Stop budgets нужны, чтобы агент не уходил в бесконечный поиск, ремонт и повторение одних и тех же действий.

## 2. Бюджеты

| Контур | Лимит | Что делать при превышении |
| --- | --- | --- |
| Broad search до гипотезы | 3-4 целевых search/read действия | Выбрать лучшую текущую гипотезу и перейти к edit или checkpoint |
| Repair loop в одном slice | 2 локальных попытки после первого провала validation | Остановиться, зафиксировать blocker и сделать один соседний hop |
| Новые edits без validation после первого substantive edit | 0 | Сначала validation, потом следующий edit |
| Одновременные edit slices | 1 активный slice | Закрыть или валидировать текущий slice до расширения |
| Повтор одного и того же failing command | 2 запуска без новых фактов | Сменить подход или зафиксировать blocker |
| Risky actions без approval | 0 | Не выполнять |

## 3. Эскалация

Если бюджет исчерпан, агент должен сделать одно из трёх:

1. зафиксировать лучший текущий вывод и пойти в соседний controlling path;
2. создать или обновить checkpoint с blocker;
3. остановиться на approval gate, если дальше начинается risky action.

## 4. Признаки дрейфа

- поиск продолжается без явной локальной гипотезы;
- новый файл читается только ради уверенности, а не ради развилки;
- в одном и том же месте идёт третий ремонт без нового сигнала;
- post-edit validation откладывается.

## 5. Правило восстановления

Если агент заметил дрейф, следующий шаг обязан быть одним из двух:

1. минимальный edit, который даст дискриминирующий сигнал;
2. минимальная validation action на уже изменённом slice.
