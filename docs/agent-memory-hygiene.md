# Agent Memory Hygiene

Дата: 2026-05-22
Статус: active

## 1. Цель

Memory hygiene нужна, чтобы memory layer оставался коротким, безопасным и пригодным к повторному использованию.

## 2. Что разрешено хранить

- validated commands;
- environment gotchas;
- устойчивые правила структуры проекта;
- краткие lessons learned;
- routing hints и execution hints, если они подтверждены практикой;
- ссылки на source-of-truth документы.

## 3. Что запрещено хранить

- секреты, токены, пароли, ключи;
- персональные данные;
- неподтверждённые гипотезы;
- длинные narrative summaries без прикладной ценности;
- дубли содержимого из state docs;
- временные мысли, которые устареют к следующей сессии.

## 4. Формат записи

Каждая запись должна быть:

1. короткой;
2. атомарной;
3. проверяемой;
4. привязанной к области применения;
5. понятной без чтения всей истории задачи.

## 5. Retention и compaction

| Сигнал | Действие |
| --- | --- |
| Две записи описывают одно и то же | Объединить или удалить дубликат |
| Запись устарела из-за изменения архитектуры | Обновить или удалить |
| Запись полезна только в одной активной сессии | Не переносить в repo memory |
| Запись длиннее, чем нужно для практического reuse | Сжать до 1-3 bullets |

## 6. Правило promotion в shared layer

Learning нужно переводить из локального контекста в shared layer, если:

- он уже один раз помог исправить или ускорить задачу;
- он описывает реальное ограничение репозитория или среды;
- без него вероятно повторение ошибки;
- он полезен не только текущей сессии.

## 7. Правило deletion

Запись должна быть удалена или переписана, если:

- она стала неверной;
- она дублирует более точную запись;
- она описывает процесс, который теперь закреплён в AGENTS, hooks или instructions;
- она превратилась в шум и больше не помогает принимать решения.

## 8. Security baseline

Если есть сомнение, можно ли хранить значение в memory layer, ответ по умолчанию: нет. Сначала убрать чувствительные данные, затем записывать только безопасный operational вывод.
