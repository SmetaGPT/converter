# Agent Baseline

Дата: 2026-05-22
Горизонт baseline: до внедрения state layer, memory discipline, hooks и release loop

## 1. Снимок исходного состояния

На старте в репозитории есть только roadmap-документ. Операционный агентный контур в git-tracked артефактах отсутствует.

Следствия:

- нет единой точки входа в статус проекта;
- нет фиксации активного спринта;
- нет релизного состояния;
- нет чекпоинтов задач;
- нет repo-memory для validated learnings;
- нет routing по режимам работы агента.

## 2. Текущий task lifecycle как есть

### Текущая последовательность

1. агент получает запрос;
2. ищет контекст напрямую в рабочей папке или диалоге;
3. формирует локальную гипотезу без формального checkpoint;
4. выполняет изменения;
5. validation и closeout происходят непоследовательно;
6. знания не переносятся в устойчивую repo-memory;
7. следующая сессия не имеет гарантированного resume path.

### Главные слабые места

- холодный reacquire зависит от случайного качества предыдущего диалога;
- отсутствует обязательный state update после завершения задачи;
- нет контролируемого места для lessons learned;
- нет отдельного release loop;
- нет формализованного handoff между сессиями.

## 3. Baseline-метрики

Часть метрик на baseline измеряется напрямую, часть фиксируется как стартовая экспертная оценка на основании отсутствия нужных артефактов. После накопления первых 5-10 задач значения должны быть пересчитаны фактическими данными telemetry.

| Метрика | Baseline | Метод фиксации |
| --- | ---: | --- |
| Холодный reacquire контекста до рабочего понимания | 15-30 минут | Экспертная оценка: нет status-entry-point и checkpoints |
| Завершённые задачи с обновлением state-документа | 0% | State layer отсутствует |
| Кодовые задачи с focused validation | 0-20% | Процесс не закреплён, поведение ситуативно |
| Повторные environment-ошибки после фиксации в repo-memory | Н/Д | Repo-memory отсутствует |
| Задачи с явным handoff / closeout | 0% | Формального closeout слоя нет |
| Выпуски с checklist и runbook | 0% | Release loop отсутствует |
| Resume из checkpoint без повторного broad search | 0% | Checkpoints отсутствуют |
| Задачи с validation target до первого edit | 0-10% | Правило не закреплено |
| Повторные broad-search циклы после начала реализации | Высокие | Нет stop budgets |

## 4. Gap analysis против целевой модели

| Целевая способность | Baseline |

## 5. Набор ключевых рисков

1. Следующая сессия без state files будет практически заново реконструировать контекст.
2. Даже полезные learnings останутся только в истории диалога, а не в repo-memory.
3. Без lifecycle hooks агент легко пропустит validation, closeout и state update.
4. Без routing implementation, review и release будут смешиваться в одном режиме.
5. Без scorecard любое улучшение останется субъективным.

## 6. Что должен дать первый цикл внедрения

Минимально достаточный прогресс после завершения roadmap:

- cold-start опирается на короткий state layer;
- активная задача восстанавливается из checkpoint;
- каждое устойчивое learning попадает в repo-memory;
- validation закреплён как обязательный шаг после первого substantive edit;
- closeout обновляет статус и handoff;
- release-ready состояние оформляется отдельным циклом.
